# Web reliability and security review — 2026-10-22

This review covers the Luo Chat web source, Vercel production project and Supabase project `byjixqwpjvsgmqilmzbm`. It records checked controls and remaining gaps, not a guarantee that every feature is defect-free.

| Area | Checked or changed | Remaining limit |

| Input validation | Auth/deletion JSON requires the JSON media type, an object and at most 16 KiB, with a body-read deadline. Password and bearer lengths are bounded. Database message/attachment checks and adversarial metadata tests pass. | Uploaded media bytes are not comprehensively malware-scanned. |
| Authorization | Every public table has RLS. Outsider message reads/sends, forged attachment metadata, private vault access and push queue privileges pass rolled-back hosted tests. Existing privileged RPC membership checks/grants remain intact. | Advisor warnings for 69 authenticated GraphQL-visible tables and 66 callable privileged RPCs require continuing per-feature review; discovery warnings alone do not prove row leakage. |

| Error handling | Call config distinguishes invalid sessions (401) from auth outages (503), returns generic errors, and validates token structure before network work. ## Applied database change

Hosted migration `20261022220505_web_reliability_hardening` was first trialled inside a rolled-back transaction, then applied and checked with `tests/web-hardening.sql`. It adds indexes, corrects quota locking and adds the message rate trigger. No real-user records were read to demonstrate access controls, and no private files were exported. Worker auth models are preserved: auth and cleanup authenticate internally, push uses a private worker bearer, and deletion retains JWT verification plus password confirmation.
