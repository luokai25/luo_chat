# Luo Chat 15.0.0 — the 15-feature release

Open **Luo tools** above your inbox, in a chat menu, or through Settings → Help. Background notification controls are also linked from Settings → Notifications and Device access. The black-and-gold theme and Luo Family stickers remain.

## Security and operations

New public tables have RLS and explicit grants. Private documents and subscriptions are owner-only; calls are restricted to their participants and current conversation membership. Albums delegate to the existing checked attachment RPC. Drawing mutations check membership, blocks, announcements and archived groups. Public SECURITY DEFINER routines have anonymous execution revoked. Worker config and queue claim/ack routines are callable only by service_role.

The push function authenticates a separate 256-bit worker bearer in its body, so its gateway verify_jwt flag is false. That is an intentional worker-authentication boundary, not an unauthenticated delivery API. It uses the existing Supabase Edge runtime service-role environment internally; no service-role key was retrieved or shipped to clients. Endpoints are restricted to known HTTPS push providers, preventing arbitrary URL fetches. Payloads contain generic alerts rather than message content or SDP.

The operator bootstrap helper is `scripts/provision-web-push.mjs`. It creates an owner-only `.env.push-provision.sql` file for a fresh database; apply only through trusted database administration. Existing configured keys are preserved. Never deploy/archive either provisioning file or `.env.push-bootstrap`. The hosted project has already been provisioned. To configure a TURN relay, set `LUO_TURN_URL`, `LUO_TURN_USER` and `LUO_TURN_PASSWORD` in Vercel server environments; credentials are returned only after authenticated call-config requests. No paid relay was provisioned in this run.

Backup encryption uses WebCrypto AES-GCM (256-bit), fresh 128-bit salt and 96-bit IV, authenticated format binding, and PBKDF2-HMAC-SHA256 with 600,000 iterations. The parser rejects arbitrary work factors and malformed/oversized envelopes before deriving a key. Guidance: https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html and https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html . These algorithm choices do not constitute an external security audit.

Run `npm run release:reproduce` on Node 24. Build inputs include API routes and reviewed Edge Function source. Existing database-baseline/restore, hosted-auth, Safe Browsing, physical-device and full application security gates remain separate; this release does not certify them.
